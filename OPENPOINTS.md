| N-14 | **MathemaSharp as the numeric engine (2026-11-06).** NDSharp references `MathemaSharp.Kernels` (BCL only). On it, for every real dtype including float16: `sum prod max min mean var std cumsum cumprod any all count_nonzero argmax argmin diff median percentile quantile` (all 13 numpy `method=` values), `sort`, `argsort` (stable, NaN last), `unique` (through argsort) and `searchsorted` (new; both sides, `sorter`, any real dtype) for the real dtypes including bool and float16 (complex keeps NumPy's lexicographic order in the engine), `matmul`/`dot` (all real and complex dtypes, any batch and layout), `cov` and `corrcoef`, `gradient`, `trapezoid`/`trapz` (new), `histogram` (new: integer or explicit bins, `range`, `density`; no weights, no bin-rule strings) and the whole `nan*` family (new: `nansum nanprod nanmean nanvar nanstd nanmax nanmin nanmedian nanpercentile nanquantile nanargmax nanargmin nancumsum nancumprod`; complex is refused). The general engine (`Red` in `Reduce.cs`) is still there as the oracle of the tests, behind `KernelPath.Begin(false)`, and for complex and the temporal dtypes; it can be deleted for the real dtypes when nobody needs that oracle any more. Tests: `KernelPathTests`, `OrderStatisticsKernelTests`, `CalculusKernelTests`, `TruthArgDiffNanKernelTests` (engine as oracle bit for bit; the nan* functions against numpy's formulas written with elementary operations). float16 is computed in float16 arithmetic as the engine did (numpy accumulates in float32: not verified here). Not compared with real numpy (not installed here). Open: `ptp` (still `max - min` on the kernels), complex `sort`/`argsort`, `partition`/`argpartition`/`lexsort`/`unique` over axes (missing), `argsort`, `unique`, `bincount`, `searchsorted`/`partition` (missing), the rest of linear algebra (`det`, `inv`, `solve`, `lstsq`, `pinv`, `svd`, `eig`), FFT, elementary functions, `inner`/`outer`/`cross`/`convolve` still run only in NDSharp. The product kernel adds left to right in the type's own arithmetic (as the engine did); NumPy uses BLAS, whose grouping differs, so the last bits can differ from real NumPy (not compared here); pack `MathemaSharp.Kernels` into the feed before NDSharp is packed (NDSharp now depends on it); a public signature change broke the prebuilt `NDSharp.Frame` once (MissingMethodException): keep old signatures as overloads. | partly done |
